# Git 워크플로우 및 자율 브랜치/커밋/병합/푸시 자동화 규칙

## 1. 커밋 메시지 포맷
모든 Git 커밋 메시지는 아래 형식을 엄격히 따른다.

```plaintext
<type>(<scope>): <한글 커밋 요약>

[선택적 본문: 변경 이유 및 상세 내용 (한글)]
```

### 허용되는 Type 8종
- `feat`: 새로운 기능 추가 (예: `feat(minwon): 민원접수대장 등록·복합 검색 및 로그인 모달 구현`)
- `fix`: 버그 및 예외 처리 수정
- `docs`: 문서 및 README 수정
- `refactor`: 기능 변경 없는 코드 구조 개선 및 모듈 분리
- `perf`: 성능 및 쿼리/메모리 최적화
- `style`: 코드 포맷팅, 스타일 수정
- `test`: 단위 테스트 및 통합 테스트 추가/수정
- `chore`: 빌드 설정, 패키지 의존성, `.gitignore`, 에이전트 규칙/스킬 설정

## 2. AI 에이전트 자율 브랜치 생성·병합·푸시 및 메인 브랜치 커밋·푸시 자동화 규칙
사용자가 매번 일일이 브랜치 생성, 병합(Merge), 커밋, 푸시를 요청하지 않더라도, AI 에이전트는 작업 단위 완료 시 스스로 판단하여 아래 절차에 따라 커밋과 원격 저장소(`origin`) 푸시까지 자동으로 수행한다.

1. **기능 브랜치 자동 생성·병합·푸시 규칙 (신규 기능 / 대규모 리팩토링 / 다중 모듈 작업)**:
   - 새로운 기능 개발이나 다중 파일 변경 작업 시작 시 작업 성격에 맞는 기능 브랜치(`feat/<기능명>`, `fix/<이슈명>`, `refactor/<대상>`)를 자동으로 생성(`git checkout -b`)하여 작업하고 단계별로 커밋한다.
   - 기능 구현이 완료되고 필수 품질 검증(`npm run typecheck`, `npm test`, `npm run build`)을 모두 통과하면, 사용자의 별도 지시를 기다리지 않고 즉시 `main` 브랜치로 전환(`git checkout main`)하여 병합(`git merge --no-ff <브랜치명>` 또는 Fast-forward)한다.
   - 병합 직후 원격 저장소가 연결되어 있다면 즉시 `git push origin main`을 자동 실행하고, 병합이 완료된 작업 브랜치는 정리(`git branch -d <브랜치명>`)한다.

2. **메인(`main`) 브랜치 직접 커밋·푸시 규칙 (단순 패치 / 설정·문서 수정 / 초기 스캐폴딩 / 핫픽스)**:
   - 초기 프로젝트 구성, 규칙/스킬 업데이트, UI 미세 조정, 단일 모듈 버그 수정 등 독립 브랜치 분기가 불필요한 소규모 작업은 `main` 브랜치에서 직접 작업한다.
   - 검증 완료 즉시 표준 한글 커밋 메시지로 `git commit`을 수행하고, 사용자 요청 없이도 자동으로 `git push origin main`을 실행하여 원격 저장소를 최신 상태로 유지한다.

3. **원격 저장소(`origin`) 상태 확인 및 안전 처리**:
   - 푸시 전 `git remote -v`로 원격 저장소(`origin`) 연결 여부를 확인하며, 연결되어 있는 경우 항상 커밋/병합과 동시에 원격 푸시까지 한 호흡으로 완료한다.
   - 만약 원격 저장소가 아직 GitHub에 생성되지 않았거나 인증/네트워크 오류가 발생하면 로컬 `main` 브랜치 병합 및 커밋까지 완료한 뒤 사용자에게 원격 푸시 상태만 간결하게 보고한다.

## 3. 저장소 보안 및 대용량 파일 관리
- `.env`, 데이터베이스 파일(`*.db`, `*.db-wal`, `*.db-shm`), 실시간 로그(`logs/`, `log/`), 로컬 참조 문서 폴더(`_ref/`, `_ref_VBA/`), 대용량 빌드 산출물(`release/`, `dist/`, `out/`, `*.exe`)은 절대 Git에 커밋하지 않는다.
