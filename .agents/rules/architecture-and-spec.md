# 민원접수대장 아키텍처, 도메인 데이터, 로그인 인증 및 내장 REST API 서버 명세 규칙

본 규칙은 기존 Excel VBA(`_ref_VBA`) 시스템의 도메인 로직과 다중 사용자 REST API 서버 모드를 결합한 `MinwonRegister`의 핵심 기술 명세를 정의한다.

## 1. 민원접수대장 13대 표준 필드 및 동적 코드 항목 규격
1. **민원접수대장 핵심 컬럼 (`minwon_records` 테이블, 기존 VBA `M~Y`열 100% 호환)**:
   - `id` (`연번`): 고유 번호 (자동 증가 또는 기존 연번 유지)
   - `receivedDate` (`접수일자`): `YYYY-MM-DD` 형식
   - `receptionType` (`접수구분`): 국민신문고, 전화민원, 공문접수, 방문민원, 경찰청이첩 등 (신규 입력 시 코드 목록에 자동 추가 지원)
   - `receptionNo` (`접수번호`): 공문/민원 접수 번호
   - `complainantName` (`이름`): 민원인 성명
   - `contact` (`연락처`): 민원인 전화번호/연락처
   - `location` (`위치`): 민원 발생 위치 또는 단속장비 설치 위치 (장비 마스터 검색/자동완성 연동)
   - `zoneType` (`구역구분`): `일반구역`, `어린이보호구역`, `노인보호구역`, `장애인보호구역` 등
   - `content` (`민원내용`): 민원 상세 내용
   - `reviewDate` (`공단 검토일자`): `YYYY-MM-DD` 형식 (미검토 시 공란 허용)
   - `reviewResult` (`공단 검토결과`): `신규설치`, `이설검토`, `기존운영`, `설치불가`, `검토중`, `지자체이관`, `수리완료` 등 동적 항목 관리
   - `improvementResult` (`개선결과`): 조치 및 개선 결과 상세
   - `note` (`비고`): 기타 참고사항 및 연결 장비번호(`deviceId`)
   - 추가 감사(Audit) 메타데이터: `createdBy`(`등록자`), `updatedBy`(`수정자`), `createdAt`, `updatedAt`

2. **빠른 기간 필터 및 복합 조건 검색 (`frmSearch` 완벽 계승 및 확장)**:
   - **빠른 기간 선택**: `전체`, `당월`, `3개월`, `6개월`, `9개월`, `금년` 원클릭 기간 자동 계산 (접수일자 기준 / 공단 검토일자 기준 각각 독립 또는 동시 적용)
   - **검색 구분**: `전체`, `접수구분`, `접수번호`, `이름`, `연락처`, `위치`, `구역구분`, `민원내용`, `개선결과`, `비고` 키워드 부분 일치 검색 및 `공단 검토결과` 필터링

## 2. 무인교통단속장비 마스터(`device.csv`) 및 운영현황 자동 통계(`operator-status.xlsx`)
1. **장비 마스터 데이터 (`devices` 테이블, 기본 487대 시드 내장)**:
   - 컬럼: `installYear`(`설치년도`), `deviceId`(`장비번호`, 예: `B7272`), `deviceName`(`장비명`), `location`(`위치`), `manufacturer`(`제조사`), `category`(`유형`: `고정식`/`이동식`), `enforcementType`(`단속종류`: `신호과속`, `과속`, `구간`, `운행제한`, `진입금지`), `speedLimit`(`제한속도`), `zoneType`(`보호구역명`: `일반구역`, `어린이보호구역`, `노인보호구역`, `장애인보호구역`)
   - 민원 등록/수정 시 장비번호나 위치 키워드로 장비를 검색하여 `위치`와 `구역구분`을 원클릭으로 자동 채울 수 있다.
2. **무인교통단속장비 유형별 운영현황 통계 (`modMain.Analysis` 완벽 구현)**:
   - 설치년도별 보호구역(`일반구역`, `어린이보호구역`, `노인보호구역`, `장애인보호구역`) 및 단속종류(`신호과속(고)`, `과속(고)`, `구간(고)`, `운행제한(고)`, `진입금지(고)`, `과속(이)`, `합계`) 매트릭스를 실시간 집계하고 `operator-status.xlsx`와 동일한 표준 양식으로 엑셀 출력한다.

## 3. 로그인 모달 폼 및 역할 기반 접근 제어 (Authentication & RBAC)
1. **로그인 모달 (`LoginModal.tsx`)**:
   - 앱 실행 시 또는 로그아웃/세션 만료 시 중앙 모달 폼으로 아이디/비밀번호 로그인을 수행한다.
   - 초기 기본 관리자 계정(`admin` / `admin1234`)을 자동 시드하며, 로그인 후 비밀번호 변경 및 사용자 계정 추가/관리가 가능하다.
2. **사용자 권한 등급 (`users` 테이블)**:
   - `ADMIN` (`관리자`): 민원/장비 전체 관리, 사용자 계정 관리, 데이터 초기화, REST API 서버 설정 변경
   - `OPERATOR` (`담당자`): 민원 등록/수정/삭제, 장비 등록/수정, 엑셀 내보내기
   - `VIEWER` (`열람자`): 민원 및 장비 현황 조회, 통계 확인, 엑셀 내보내기 전용

## 4. 내장 REST API 서버 및 다중 사용자 동시 접속 아키텍처
1. **서버 모드 On/Off 및 실시간 구동**:
   - Electron Main 프로세스 내부에 Node.js HTTP REST API 서버(`src/main/server/rest-server.ts`)를 내장한다.
   - 사용자가 사이드바 하단 또는 설정 탭에서 **서버 기능(`다중 접속 서버`)**을 켜면 지정된 포트(기본 `8090`, `0.0.0.0` 바인딩)로 즉시 기동되고, 로컬 LAN IP 주소 목록(예: `http://192.168.0.10:8090`)을 화면에 안내한다.
2. **REST API 엔드포인트 및 웹 클라이언트 동시 서빙**:
   - 서버 활성화 시 `/api/v1/*` 경로로 JSON REST API(`POST /api/v1/auth/login`, `GET/POST/PUT/DELETE /api/v1/minwon`, `GET/POST/PUT/DELETE /api/v1/devices`, `GET /api/v1/stats`, `GET/PUT /api/v1/codes`, `GET /api/v1/export/*`)를 제공한다.
   - 동시에 동일한 React Renderer 빌드 산출물을 정적 웹 앱으로 서빙하며, 프론트엔드 브릿지(`src/renderer/services/api-client.ts`)는 Electron IPC 환경(`window.minwonApi`)과 일반 웹 브라우저/원격 접속 환경(`fetch('/api/v1/...')` + `Bearer <token>`)을 자동 감지하여 **다른 PC 사용자가 웹 브라우저나 클라이언트 앱으로 접속해도 100% 동일한 로그인 모달과 민원접수대장 UI**를 사용할 수 있게 한다.
   - 실시간 변경 동기화를 위해 Server-Sent Events(`GET /api/v1/events`) 및 Electron IPC 브로드캐스트를 함께 지원하여, 한 사용자가 민원을 등록/수정하면 접속 중인 다른 사용자 화면에도 즉시 반영된다.
